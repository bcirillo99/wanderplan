# Product

## Register

product

## Users

Group of up to 5 travel companions, led by one primary planner. Heavy planning sessions happen on desktop (before the trip); on-the-go coordination and reference happens on mobile (during the trip). Both contexts are primary workflows — not afterthoughts.

## Product Purpose

All-in-one trip planning tool: flights, accommodations, activities, transport, packing, budget, notes — organized around trips and days. Success means a group can plan a complex multi-destination trip without losing track of any detail, and reference it comfortably on a phone while boarding a plane.

## Brand Personality

Warm, precise, confident.

Airbnb DNA: coral/Rausch warm accent on clean white and warm-neutral backgrounds. Photo-first cards that make destinations feel tangible. Expandable pill-shaped inputs for search and filters. Strong typographic hierarchy with generous whitespace. Reliable, premium, bright.

## Anti-references

- Dark SaaS dashboards (Linear, Vercel, Raycast dark) — no dark vibes, no cool-blue grays
- Generic Bootstrap admin panels — no boxed cards, no default-looking table layouts, no muted-gray everything
- Nature-themed travel blogs — no forest green palettes, no earthy serif-everything aesthetic
- Generic "travel app" coral-plus-map-pin clichés — the Airbnb reference is about the design system quality, not surface-level iconography

## Design Principles

1. **Photo first, data second.** Every trip has a cover image. That image anchors the experience; text and data layer with it, never fight it.
2. **Warmth through one accent.** A single warm coral does all the work. Neutrals carry everything else. Adding a second accent color is a failure.
3. **Precision earns trust.** Five people are coordinating from this tool. Misaligned elements, bad contrast, inconsistent spacing — all undermine confidence in the data itself.
4. **Mobile is real work.** On-the-go mobile isn't a read-only viewer. It's where people check flights, mark packing items, and add notes in real time. Design for touch and speed.
5. **Hierarchy over density.** There are 10 data categories per trip. The interface must surface what matters now (today's activities, upcoming flight) without hiding everything else.

## Accessibility & Inclusion

Best-effort. Hard requirements: no low-contrast text (minimum 4.5:1 for body, 3:1 for large text), all interactive elements properly aligned and touch-target sized (minimum 44px on mobile). Reduced motion support preferred but not blocking.
